LINKS DIRECTORY — INSTALLATION GUIDE
===================================

This is a self-hosted PHP + MySQL directory for tracking device
connection info (video conferencing links, IPs, credentials, etc.)
organized by Entity > School > Device — adaptable to any organization
that needs a structured, permission-controlled connection directory,
with role-based accounts, Single Sign-On, two-factor authentication,
and CSV import.

--------------------------------------------------------------------
1. WHAT'S IN THIS PACKAGE
--------------------------------------------------------------------
docker-compose.yml       - the two/three container stack (web, db, tls-proxy)
init.sql                 - full database schema for a FRESH install
migration_*.sql          - individual historical migrations (only needed if
                           you're upgrading an existing older database that
                           predates this package — a fresh install only
                           needs init.sql)
.env.example             - copy this to .env and fill in real values
deploy.sh                - convenience script: fixes file ownership/
                           permissions and restarts the web container after
                           you copy in new files
html/                    - the application itself
tls-proxy/               - nginx + Certbot container for automatic HTTPS
                           via DNS-01 challenge (currently wired for DNS
                           Made Easy specifically — see note in section 4)

--------------------------------------------------------------------
2. PREREQUISITES
--------------------------------------------------------------------
- A Linux host (this was built and tested on Debian) with Docker and
  Docker Compose installed
- A domain name you control, with the ability to add DNS records
- If using SSO: a Google Cloud Console project (and/or a Microsoft Entra
  tenant) to register an OAuth client
- If using password-reset emails: a Gmail account with an App Password
  (or another SMTP provider — see .env.example)

--------------------------------------------------------------------
3. FIRST-TIME SETUP
--------------------------------------------------------------------
1. Copy this entire folder to your server, e.g. /opt/links-app/
2. cp .env.example .env
   chmod 600 .env
3. Edit .env and fill in real values:
   - DB_PASSWORD / DB_ROOT_PASSWORD: pick strong passwords
   - INITIAL_ADMIN_USERNAME / INITIAL_ADMIN_PASSWORD: the first admin
     account, auto-created on first boot if admin_users is empty
   - DOMAIN: your actual domain
   - LETSENCRYPT_EMAIL: a real email you check (Let's Encrypt expiry
     notices)
   - DNSMADEEASY_API_KEY / DNSMADEEASY_SECRET_KEY: only if you use DNS
     Made Easy (see section 4 if you use a different DNS provider)
   - SMTP_* : only needed if you want Forgot Password emails to work
4. docker compose up -d
   This builds/starts three containers: web (PHP-FPM + nginx), db
   (MySQL), and tls-proxy (obtains and renews your TLS certificate).
5. On first boot, the web container automatically runs init.sql against
   an empty database and creates your initial admin account from the
   .env values above.
6. Visit https://yourdomain/ and log in with the initial admin account.
7. Immediately go to Users and set a real password / consider enabling
   2FA on that account, since the .env password was just sitting in a
   plaintext file.

--------------------------------------------------------------------
4. IF YOU DON'T USE DNS MADE EASY
--------------------------------------------------------------------
tls-proxy/Dockerfile installs the certbot-dns-dnsmadeeasy plugin
specifically. Certbot supports many other DNS providers (Cloudflare,
Route53, DigitalOcean, etc.) via their own plugins. To swap providers:
1. Change the pip install line in tls-proxy/Dockerfile to your
   provider's certbot plugin (e.g. certbot-dns-cloudflare)
2. Update tls-proxy/entrypoint.sh's credential file and the
   --dns-<provider> flags to match that plugin's expected format
3. Update the corresponding .env variables

--------------------------------------------------------------------
5. DEPLOYING CODE CHANGES LATER
--------------------------------------------------------------------
Standard flow for any file change:
  scp <changed files> user@server:~/
  sudo mv ~/<file> /opt/links-app/html/<correct subfolder>/
  /opt/links-app/deploy.sh

deploy.sh fixes ownership/permissions (the container's own entrypoint
re-asserts ownership on every restart, which otherwise blocks you from
re-editing files) and restarts the web container.

For a database change, copy the SQL file into the db container and run
it with `source`, rather than piping through stdin with -it (the two
don't mix):
  docker cp migration_file.sql links-db:/tmp/
  docker exec -it links-db mysql -u root -p linksdb -e "source /tmp/migration_file.sql"
  docker exec links-db rm -f /tmp/migration_file.sql

--------------------------------------------------------------------
6. FEATURE OVERVIEW
--------------------------------------------------------------------
- Roles: Viewer (lookup only), Editor (+ Devices/Locations/Platforms,
  optionally restricted to specific Entities), Admin (everything)
- Platforms (Zoom/Teams/Meet/Polycom, or your own) each define their own
  custom fields, with per-field "hide from viewer" support
- Import: CSV bulk import for Platforms, Devices, and Users
- Forgot Password: email-based reset flow (requires SMTP configured)
- Two-Factor Authentication: TOTP-based, with a QR code (via the
  endroid/qr-code Composer package — see section 8 below, this must be
  installed for the Security page to work) plus manual key entry as a
  fallback
- Single Sign-On: Google and/or Microsoft, multiple connections
  supported simultaneously, each with its own allowed email domain and
  optional per-email-prefix role assignment
- Session timeout: 30 min default, 4-hour "stay logged in" option, with
  a live countdown shown in the sidebar

--------------------------------------------------------------------
8. INSTALLING THE QR CODE LIBRARY (required for 2FA setup to work)
--------------------------------------------------------------------
The 2FA setup page generates its QR code using endroid/qr-code (backed by
bacon/bacon-qr-code for the actual encoding) — a well-established,
widely-used Composer package, not custom code. This must be installed
before /security.php's 2FA setup screen will load.

Check your container's PHP version first, since that determines which
package version to install:
  docker exec links-web php -v

Then, from the host (not inside the web container), run Composer as a
one-off tool against your html/ folder — this does not require Composer
to be installed inside the web container itself:
  docker run --rm -v /opt/links-app/html:/app -w /app composer:latest require "endroid/qr-code:^4.0"

(^4.0 works with PHP 8.1/8.2. If your container runs PHP 8.4+, you can
use the latest version instead: drop the version constraint entirely.)

This creates composer.json, composer.lock, and a vendor/ folder inside
html/ — commit the first two to version control, but add vendor/ to
.gitignore and run `composer install` (via the same docker run pattern,
swapping `require ...` for `install`) after cloning instead.

--------------------------------------------------------------------
9. ENCRYPTION KEY FOR SSO SECRETS
--------------------------------------------------------------------
SSO client secrets are encrypted at rest using a key that lives only in
.env, never in the database. Generate your own (don't reuse an example
you find anywhere, including this file):
  docker exec links-web php -r "echo base64_encode(random_bytes(32));"

Put the result in .env as APP_ENCRYPTION_KEY. If you're adding this to
an existing install that already has SSO connections saved from before
this feature existed, you'll need to edit and re-save each one (re-enter
its Client Secret) after deploying — their previously-stored plaintext
secrets won't decrypt automatically.

Losing this key later means every saved SSO connection's secret becomes
unreadable and needs to be re-entered — back it up like any other secret
in .env.

--------------------------------------------------------------------
7. SECURITY REMINDERS BEFORE GOING LIVE
--------------------------------------------------------------------
- Never commit .env to version control — only .env.example
- Rotate any password that was ever typed into a chat, email, or ticket
- Confirm only ports 80/443 are reachable from the internet
- Back up regularly, and actually test a restore at least once
